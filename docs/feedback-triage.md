# 反馈与进度：维护指南

主 App 的「设置 → 反馈与进度」提供问题、建议和 Issues 链接。第一版由用户在 GitHub 以自己的账号确认提交，官方 Issues 是记录和进度入口；App 不读取或上传语音、转写、剪贴板、日志或账号凭据。

- **来源**：按 GitHub 作者区分投稿。只有核实过的项目维护者、测试者或受邀创作者才设置相应内部标记；用户自报的场景不是认证。无需询问真实姓名或联系方式。
- **优先级**：输入丢失、功能不可用或疑似隐私问题先审；其他按影响与可复现性排序。开发者或受邀创作者反馈可优先初审，不覆盖紧急程度。
- **重复反馈**：回复并链接主 Issue，保留各作者自己的复现。用评论说明已确认、处理中、待验证或已发布；发布后注明版本，不把合并当作上线。
- **隐私**：匿名/无 GitHub 账号的私有收件和回执，以及开发者个人 Token 直提均非第一版功能。不要在公开 Issue 粘贴含隐私的截图、日志或凭据。

## 发布前验收

表单在默认分支生效后，登录 GitHub 验证两个入口确实打开对应表单，无需提交公开测试 Issue。在 16e 上检查 App 能显示版本，能打开表单、退出登录流程后返回设置，并能从 Issues 找到一条已有反馈。Linux 静态检查不能替代这些步骤。

静态检查（需 PyYAML）：`python -m unittest discover -s Tests/Feedback -v`。
