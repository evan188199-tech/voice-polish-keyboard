# Private reference prototype boundaries

The current prototype accepts only the demo adapter or a user-selected local JSON preview. Import preview, material selection and approved text/image references are bound to the current in-memory account and generation. A new preview invalidates the prior preview; switching account or revoking clears previews, terms, material and permits. Only registered current demo-source items can be used; every copy/share action must recheck verification, channel, expiry, version, customer access (for links), and explicit selection.

Search operates only on confirmed current-session terms and current demo material titles. The main app offers explicit local-only expiring clipboard copies and the system share sheet. These are draft/user actions, not messages sent or proof that a recipient can access a file. Copied text carries a transient-private pasteboard type, and the keyboard's sampling path checks that type before reading, to avoid adding these copies to clipboard history. The test uses a fake pasteboard; actual type preservation and cross-process behavior are not yet verified. This marker cannot remove existing clipboard history or protect content copied again by another app. Clipboard and share host behavior require iOS testing. Images are generated demo placeholders, not fetched assets. Private indexes are memory-only and are lost on logout or process exit.

`keyboardSnapshot` intentionally returns nil. The current bridge and entitlements do not establish an approved private account-data channel. The keyboard cannot yet search or copy private references, and the app has no real Notion login, connector, credentials, or synchronization.

Before a real integration: explicitly authorize the chosen account and specific sources with a supported least-privilege, read-only flow; verify source schema, field allowlist, freshness, revocation and account isolation; obtain independent verification that each customer-facing link/image has appropriate access, attribution, channel and expiry; define protected local persistence excluding unintended backup/sync; verify signed app-group entitlements or another supported authenticated minimal-data transport; implement and test client-side revalidation and host-specific copy/share behavior. No source permission or readable page alone proves customer file access. Never put source URLs, secrets, private content, or production credentials into code, fixtures, logs or public issue discussions.
