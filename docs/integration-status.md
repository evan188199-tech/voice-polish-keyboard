# Integration status (2026-11-14)

The `codex/complete-keyboard` checkout combines the preserved product and device-safety checkpoints. This is work in progress, not a release or a completed device acceptance.

The voice-page return key and English top-row key were visible and hittable; tapping `q` inserted it and delete removed it. A second test fed the same public PCM into the real coordinator and TCP bridge, confirming one nonempty result and no repeated delivery. Model, tokens and audio were checked against the [upstream release](https://huggingface.co/csukuangfj/sherpa-onnx-sense-voice-zh-en-ja-ko-yue-int8-2025-09-09/commit/355f4d4884d8afd08aef04b9007a8556d7b463b2). Simulator tests passed for hashing and for rejecting a fictional corrupt model that previously triggered a native crash. Updating the model requires reviewing and updating the revision and both digests together. This guards file integrity, not native-library bugs or device compatibility.

The production translation service still defaults to disabled. Separately, `bash scripts/check_macos_translation_bridge.sh` uses a loopback server and fictional text to verify that a held request does not block cancellation or a later request, and that cancelling the local request closes its connection. This macOS transport test is not an iPhone audio or host-insertion test.

- `scripts/test_portable.sh` and `scripts/check_translation.sh` passed their logic/mock checks. The device installation and engineering guardrail suites passed 6 and 5 mock tests respectively. None of these checks uses a real model provider or proves real-device behavior.
- The regenerated Xcode project includes translation and shared sources in their appropriate targets. Clipboard mirror persistence no longer depends on an asynchronously published UI update.
- The bridge listener now binds explicitly to IPv4 loopback and limits each JSON frame to 1 MiB. An iOS simulator test exercises a real TCP ping, and the complete simulator suite passes 106 tests. Oversized traffic closes the connection instead of being truncated. The device behavior and external-interface isolation have not yet been tested on an iPhone.
- Clipboard sampling now requires an enabled main-app setting in a successful bridge ping. Disabled, missing legacy settings, and failed connections do not trigger a read; an enabled setting permits at most one sample per keyboard appearance. The existing first-install default remains enabled. This is covered by portable bridge mocks; actual iOS pasteboard permissions still need device validation.
- Ordinary dictation rejects provider output that changes signed numeric tokens, decimal separators, dates, currency or percent symbols, including in short text. A mock provider check exercises rejection and selection of the local text; it is not an end-to-end coordinator test. A full simulator run passed 108 tests before a subsequent whitespace-sign refinement, which was checked with targeted simulator and portable tests. The literal guard is conservative and does not prove semantic fidelity.
- History entries can open an editable local draft and preview a unique, explicit spoken-correction pattern before user confirmation. History is not mutated and external fields are not rewritten. The entered explanation is text; cross-segment voice correction and real-device UI remain unverified. A simulator suite passed 110 tests before subsequent UI and quote-boundary refinements; targeted simulator and portable checks cover those changes.
- A place-review draft is retained if insertion is unavailable; deferring it stores a held result and blocks later delivery until explicit insertion or skip. Portable mocks cover ordering, keyboard reconstruction and interruption between the two persistence writes. A simulator suite of 110 tests passed after the core change; the later status-message change is covered by portable checks. Actual host insertion has no acknowledgement and remains unverified on device.
- The voice page shows a direct recovery action when a held result exists, and status polling no longer hides that state behind a generic queue label. This explains one possible cause of an apparent “等待插入” stall, but a screenshot alone cannot establish the installed build or exact cause. Translation preview and original insertion require a currently available insertion callback; held and preview translations survive reconstruction and prevent queued translations from overwriting them. Recovery inserts before releasing the next result. These paths were tested with mocks; a 112-test simulator suite preceded the final translation-order refinement, which passed targeted mock checks and a simulator build. Visual layout and actual host insertion remain unverified.
- A simulator test injects a fake transcriber and model into the actual coordinator: “在不在” produces a mock answer in enabled question mode and remains a transcript in ordinary dictation. Missing API credentials, model errors and ASR errors are returned in order instead of being silently skipped; the recognized source is retained in history. Keyboard error presentation is separately covered with a fake bridge. No live model or audio was used for these checks.
- The simulator also exercises the real TCP client and server around the mocked coordinator: failure and answer arrive in order, a consumed answer is not replayed, stopping the bridge closes accepted connections, and restarting allows reconnection. The full simulator suite passed 113 tests. This does not verify microphone capture, extension lifecycle or insertion in a third-party iPhone host.
- Short dictation now rejects changed explicit negation markers and, when such markers exist, changed lexical order. This is a conservative fallback rule, not proof of semantic equivalence.
- At the user's request, an existing `glm-5.3-flash` gateway was tested with a short synthetic question. The repository's actual Swift API adapter succeeded from macOS through a temporary SSH tunnel; a separate temporary Tailscale HTTPS route returned 401 without credentials and 200 with the existing credential. The route and tunnel were closed after testing. The HTTPS request was not made by the iOS app, and device DNS and credentials have not been configured or verified. No credential or private endpoint is stored in this repository.

## Outstanding

- The iPhone 16e already has `com.voicepolish.app` version 2.0 installed; no application was installed or replaced during this integration. Its existing data and version need a safe deployment decision.
- The personal development identity and existing profiles were rechecked: both app and keyboard profiles cover the connected iPhone and use team the configured development team. A subsequent signed device build using that explicit team succeeded and its signature verified outside the sandbox; an earlier build with a different team failed. No automatic provisioning or device registration was attempted. The signed build has the same app identifier and version as the installed app; it has not been installed.
- Direct delivery remains fail-closed until input-field continuity can be established safely; users must explicitly recover and insert dictation or translation. The production translation bridge is disabled. These are product gaps, not successful end-to-end translation or automatic insertion.
- The bridge's build-time token is embedded in source and is not a secret or proof of peer identity. Loopback binding reduces network exposure but does not authenticate other local processes or protect against a process occupying the port. Do not enable sensitive private-material sharing on this basis.
- Idle microphone lifecycle, app switching, interruptions, real ASR, multiple hosts, accessibility, device screenshots and all other device acceptance items remain unverified. See `translation-target-safety.md`, `translation-checkpoint.md` and the relevant GitHub issues for boundaries and acceptance criteria.
