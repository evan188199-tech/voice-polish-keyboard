# 语音优先键盘：本轮实现与验收

对应 #1（尤其 issuecomment-6868741751）。核心 UI 已实现，iOS 编译、截图和真机验证尚未完成。

## 交互与差异

| 原实现 | 本轮实现 |
| --- | --- |
| 整块长按区，松开提交、左滑取消 | 中央圆形主按钮，点击开始、再次点击完成；显式取消只停止当前录音 |
| 顶部同时显示四种模式 | 顶部紧凑状态、粤英/输出字体、模式与更多菜单 |
| 按钮切换文字页 | 左右横滑切换语音/ABC；保留按钮方便 VoiceOver |
| 处理状态占用录音提示 | 录音状态与队列进度分开；处理上一段时仍可录下一段 |
| 连接时直接取消远端录音 | 从主 App 快照重建录音与计时；键盘消失时取消现场录音、保留已提交段 |
| 多个独立结果轮询 | 单一结果消费者，复用 OrderedDeliveryCursor；仅本次键盘出现后提交的任务自动插入 |

本轮统一为点击模式，不保留旧长按提交，因此没有长按/左滑取消/上滑翻译的冲突。上滑没有命令；翻译、选区语音编辑、撤回和主 App 导航重组留待后续。问答仍是明确选择的独立模式，不由普通口述问题自动触发。

语音页主要控件目标尺寸至少 44pt；主按钮 76pt；采用系统色和 SF Symbols，无参考产品的商标、素材或源码。文字页沿用原 QWERTY、数字和剪切板能力。小屏、横屏、大字体、VoiceOver 和触控命中仍需真机核验。

## 状态和恢复

| 状态 | 画面与操作 |
| --- | --- |
| 连接/冷启动 | 连接指示；确认连接前不显示录音；需准备时为轮廓麦克风，点击打开主 App |
| 权限拒绝/缺模型 | 主 App 错误快照与打开 App 入口；没有波形或录音计时 |
| 就绪 | 实心麦克风和“点击说话”；空闲不开始新的 capture |
| 启动/提交/取消中 | 主按钮进度指示，重复点击不提交第二次；禁止横滑和改模式 |
| 主 App 确认录音 | 波形图标、主 App 时间、“再次点击完成”、显式取消；不可横滑 |
| 排队/识别/润色/待插入 | 单独队列行，主录音按钮仍可用；取消下一段不清空队列 |
| 连接中断 | 不重发可能已提交的 finish；重新连接查队列；历史保留文本 |
| 返回键盘/切宿主后旧结果 | 只保留供手动插入或复制，避免意外写进新宿主 |
| 宿主拒绝插入 | iOS 没有插入成功回执，不能可靠检测；最近结果先存键盘本地，更多菜单可插入/复制，主 App 有完整历史 |

转写完成仅调用 insertText(text)，不会调用回车。回车按钮由用户明确操作，并遵循宿主语义。人工重新插入可能重复，菜单注明。Bridge 增加 4 秒请求上限，避免主 App 挂起但 TCP 未断导致键盘永久等待；取消未获确认时请打开主 App 检查。极端断线发生在服务端消费结果与客户端收到文本之间时，以主 App 历史恢复；本轮未引入持久 ACK 协议，不宣称跨进程恰好一次交付。

## 可复现验证

`SWIFTC=/path/to/swiftc ./scripts/test_portable.sh` 使用 Swift 6 编译真实的 ViewModel、Bridge adapter、协议、录音 UI 状态机、手势策略和顺序游标，以 mock Bridge 执行测试。Linux 的 Combine/UIKit 接口仅用测试替身；不验证 SwiftUI 渲染、Combine 通知、Network 或 AVFoundation。测试不创建任何模型 API 请求。

覆盖：权限/模型/主 App 不可用、快速连续点击 start/finish、取消不清队列、上一段处理时继续录音、乱序完成按序插入、重复轮询、重连采纳主 App 状态、键盘隐藏取消现场录音、旧宿主结果不自动插入、finish 回包丢失不重交、旧 Bridge 快照解码、原生顺序游标。

源码另用 Swift frontend 做语法解析；这不等于 iOS SDK 类型检查或构建。
